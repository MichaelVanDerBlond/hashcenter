# HashCenter Naming Conventions

Version: R0.1

-------------------------------------------------------------------------------
# Назначение

Документ определяет единые правила именования компонентов проекта.

Главная цель —

чтобы любой разработчик и любой ИИ называли одинаковые вещи одинаково.

-------------------------------------------------------------------------------
# Общие правила

Имена должны быть:

- понятными;
- короткими;
- однозначными;
- отражать ответственность.

Запрещается использовать сокращения,
если они не являются общеупотребительными.

-------------------------------------------------------------------------------
# Пакеты

Используются только существительные.

Правильно

config

repository

services

database

scanner

jobs

hashcat

handlers

Неправильно

helpers

misc

common

utils

manager

new

temp

-------------------------------------------------------------------------------
# Структуры

Используются существительные.

User

Job

Dictionary

Capture

Hash

Session

Upload

Result

-------------------------------------------------------------------------------
# Интерфейсы

Интерфейс описывает возможность,
а не реализацию.

Правильно

Repository

Storage

Runner

Parser

Scanner

Неправильно

RepositoryInterface

HashcatInterface

ServiceInterface

-------------------------------------------------------------------------------
# Сервисы

Каждый сервис отвечает за одну область.

Название:

<Область>Service

Примеры

JobService

UploadService

DictionaryService

ScannerService

-------------------------------------------------------------------------------
# Repository

Название:

<Сущность>Repository

Примеры

JobRepository

DictionaryRepository

UploadRepository

-------------------------------------------------------------------------------
# Handler

Название:

<Область>Handler

Примеры

UploadHandler

JobHandler

DictionaryHandler

-------------------------------------------------------------------------------
# Engine

Используется только для самостоятельных подсистем.

Допустимо

HashcatEngine

RuleEngine

SchedulerEngine

Недопустимо

UploadEngine

ConfigEngine

HelperEngine

-------------------------------------------------------------------------------
# Parser

Используется только при преобразовании данных.

Примеры

HashcatParser

CaptureParser

ResultParser

-------------------------------------------------------------------------------
# Scanner

Используется только для анализа.

Scanner не изменяет данные.

Scanner ничего не сохраняет.

Scanner ничего не запускает.

-------------------------------------------------------------------------------
# Manager

Использование Manager запрещено.

Вместо него необходимо определить
реальную ответственность.

-------------------------------------------------------------------------------
# Helper

Использование Helper запрещено.

-------------------------------------------------------------------------------
# Utils

Использование Utils запрещено.

Если появляется Utils —

архитектура требует пересмотра.

-------------------------------------------------------------------------------
# Common

Использование Common запрещено.

-------------------------------------------------------------------------------
# Generic

Запрещается создавать GenericService,
GenericRepository,
GenericManager.

-------------------------------------------------------------------------------
# Функции

Название должно начинаться с действия.

CreateJob()

StartJob()

PauseJob()

ResumeJob()

AnalyzeCapture()

ScanDictionary()

LoadConfig()

SaveResult()

-------------------------------------------------------------------------------
# Булевы значения

Используются префиксы

Is

Has

Can

Should

Примеры

IsRunning

HasErrors

CanResume

ShouldRetry

-------------------------------------------------------------------------------
# Константы

Используются PascalCase.

DefaultPort

DefaultTimeout

MaxUploadSize

-------------------------------------------------------------------------------
# Переменные

Используются короткие,
но понятные имена.

Допустимо

job

cfg

repo

db

ctx

logger

Недопустимо

x

obj

temp

test2

-------------------------------------------------------------------------------
# Файлы

Имена файлов —

нижний регистр.

Слова разделяются символом "_".

Примеры

job_service.go

upload_handler.go

dictionary_repository.go

capture_parser.go

-------------------------------------------------------------------------------
# Главное правило

Название должно объяснять ответственность.

Если по названию невозможно понять,
что делает компонент,

значит название выбрано неправильно.
