# HashCenter Project Glossary

Version: R0.1

-------------------------------------------------------------------------------
# Назначение

Данный документ определяет терминологию проекта HashCenter.

Любой разработчик и любой ИИ обязаны использовать определения,
приведённые в этом документе.

Запрещается использовать разные названия для одного и того же понятия.

-------------------------------------------------------------------------------
Capture

Файл, содержащий данные,
полученные в результате перехвата Wi-Fi трафика.

Capture может иметь различные форматы:

- pcap
- pcapng
- hc22000
- hccapx
- другие поддерживаемые форматы

-------------------------------------------------------------------------------
Hash

Данные,
которые могут быть переданы Hashcat
для восстановления пароля.

-------------------------------------------------------------------------------
Dictionary

Файл,
содержащий список возможных паролей.

Dictionary является самостоятельной сущностью проекта.

-------------------------------------------------------------------------------
Rule

Файл правил Hashcat,
изменяющий слова словаря
во время выполнения атаки.

-------------------------------------------------------------------------------
Mask

Описание шаблона перебора паролей.

-------------------------------------------------------------------------------
Attack

Способ восстановления пароля.

Примеры:

Dictionary Attack

Mask Attack

Hybrid Attack

Combinator Attack

-------------------------------------------------------------------------------
Job

Основная единица работы HashCenter.

Job содержит:

- источник данных;
- параметры атаки;
- используемые словари;
- правила;
- состояние;
- результаты.

Любая атака всегда является Job.

-------------------------------------------------------------------------------
Queue

Очередь задач,
ожидающих выполнения.

-------------------------------------------------------------------------------
Worker

Компонент,
выполняющий Job.

-------------------------------------------------------------------------------
Session

Информация о текущем состоянии выполняемой задачи.

-------------------------------------------------------------------------------
Result

Информация,
полученная после завершения Job.

-------------------------------------------------------------------------------
Scanner

Подсистема анализа файлов.

Scanner никогда:

- не запускает Hashcat;
- не изменяет Database;
- не изменяет файлы.

Scanner только анализирует.

-------------------------------------------------------------------------------
Repository

Подсистема хранения данных.

Repository никогда:

- не содержит бизнес-логику;
- не запускает процессы;
- не взаимодействует с Web.

-------------------------------------------------------------------------------
Service

Подсистема бизнес-логики.

Service управляет всеми процессами проекта.

-------------------------------------------------------------------------------
Handler

HTTP-интерфейс проекта.

Handler только принимает запросы
и вызывает Service.

-------------------------------------------------------------------------------
Engine

Автономная подсистема,
имеющая собственный жизненный цикл.

Примеры:

Hashcat Engine

Scheduler Engine

-------------------------------------------------------------------------------
Workspace

Рабочая область проекта.

Содержит:

- uploads
- results
- logs
- data

-------------------------------------------------------------------------------
Project Root

Корневая директория репозитория.

-------------------------------------------------------------------------------
Configuration

Совокупность параметров,
необходимых для запуска проекта.

-------------------------------------------------------------------------------
History

История выполненных Job.

-------------------------------------------------------------------------------
Statistics

Информация о производительности,
результатах и состоянии проекта.

-------------------------------------------------------------------------------
Node

Отдельный экземпляр HashCenter.

В будущем несколько Node могут образовывать кластер.

-------------------------------------------------------------------------------
Cluster

Несколько Node,
работающих совместно.

-------------------------------------------------------------------------------
Task

В проекте HashCenter термин Task не используется.

Используется исключительно термин Job.

-------------------------------------------------------------------------------
Manager

Термин Manager не используется.

Необходимо использовать название,
отражающее ответственность компонента.

-------------------------------------------------------------------------------
Helper

Термин Helper не используется.

-------------------------------------------------------------------------------
Utils

Термин Utils не используется.

-------------------------------------------------------------------------------
Главное правило

Каждое понятие проекта имеет одно официальное название.

Если возникает новое понятие,
оно должно быть добавлено в данный документ
до появления в исходном коде.
