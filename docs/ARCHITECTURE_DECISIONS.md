# Architecture Decision Record (ADR)

Version: R0.1

-------------------------------------------------------------------------------
# Назначение

Данный документ фиксирует архитектурные решения проекта HashCenter.

Каждое важное решение должно быть задокументировано.

Изменение ранее принятого решения допускается только после создания новой записи ADR.

-------------------------------------------------------------------------------
ADR-0001

Название

HashCenter является самостоятельной системой,
а не оболочкой над Hashcat.

Статус

Accepted

Причина

Hashcat отвечает исключительно за вычисления.

HashCenter отвечает за:

- хранение данных;
- управление заданиями;
- пользовательский интерфейс;
- историю;
- автоматизацию;
- масштабирование.

Последствия

Hashcat можно заменить другой вычислительной системой без изменения архитектуры.

-------------------------------------------------------------------------------
ADR-0002

Название

Использование SQLite.

Статус

Accepted

Причина

Для одного узла SQLite быстрее,
проще в сопровождении
и не требует отдельного сервера.

Последствия

Repository не должен зависеть
от конкретной СУБД.

При необходимости SQLite может быть заменена.

-------------------------------------------------------------------------------
ADR-0003

Название

Разделение на слои.

Статус

Accepted

Структура

Handler

↓

Service

↓

Repository

↓

Database

Причина

Минимальная связанность.

Простое тестирование.

Лёгкая замена компонентов.

-------------------------------------------------------------------------------
ADR-0004

Название

Hashcat работает отдельным процессом.

Статус

Accepted

Причина

Hashcat является внешним приложением.

Он не должен встраиваться
в процесс HashCenter.

Последствия

HashCenter управляет жизненным циклом процесса.

-------------------------------------------------------------------------------
ADR-0005

Название

Каждая подсистема имеет одну ответственность.

Статус

Accepted

Примеры

Scanner

только анализирует.

Repository

только хранит данные.

Service

только бизнес-логика.

Handler

только HTTP.

-------------------------------------------------------------------------------
ADR-0006

Название

Минимальные изменения.

Статус

Accepted

Причина

Каждое изменение должно:

использовать существующий код;

не создавать дублирование;

не ломать архитектуру.

-------------------------------------------------------------------------------
ADR-0007

Название

Запрет циклических зависимостей.

Статус

Accepted

Причина

Циклические зависимости делают проект
сложным для сопровождения.

При появлении цикла
архитектура должна быть пересмотрена.

-------------------------------------------------------------------------------
ADR-0008

Название

Документация является частью проекта.

Статус

Accepted

Причина

Изменение архитектуры без изменения документации запрещено.

Любой Pull Request,
изменяющий архитектуру,

обязан обновить соответствующие документы.

-------------------------------------------------------------------------------
ADR-0009

Название

ИИ является помощником,
а не источником архитектурных решений.

Статус

Accepted

Причина

ИИ обязан соблюдать существующую архитектуру.

Любое предложение изменить архитектуру
должно сопровождаться объяснением причин,
ожидаемых преимуществ и возможных рисков.

-------------------------------------------------------------------------------
ADR-0010

Название

Обратная совместимость.

Статус

Accepted

Причина

Любое изменение должно по возможности сохранять совместимость
с существующими структурами данных,
API и пользовательскими сценариями.

Несовместимые изменения допускаются
только при наличии отдельного ADR.

-------------------------------------------------------------------------------
Правила добавления новых ADR

Каждая запись должна содержать:

Название

Статус

Контекст

Принятое решение

Причины

Последствия

Возможные альтернативы

-------------------------------------------------------------------------------
Главный принцип

Архитектурное решение считается частью исходного кода.

Если решение изменилось —

должен измениться ADR.
