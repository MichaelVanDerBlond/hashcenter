Любое серьёзное изменение архитектуры должно быть отражено здесь.

-------------------------------------------------------------------------------
# Эволюционные принципы

Проект развивается постепенно.

Каждая версия должна быть полностью работоспособной.

Новая функциональность должна расширять существующую архитектуру,
а не заменять её.

-------------------------------------------------------------------------------
# Что считается ошибкой

Добавление новой функциональности,
ломающей существующую архитектуру.

Переписывание стабильного компонента
без объективной причины.

Добавление новой подсистемы
без регистрации в PROJECT_REGISTRY.md.

Изменение архитектуры
без обновления ADR.

-------------------------------------------------------------------------------
# Правила развития

Каждая новая версия должна:

сохранять читаемость проекта;

уменьшать сложность;

повышать расширяемость;

не создавать дублирование;

оставаться совместимой
с существующей архитектурой.

-------------------------------------------------------------------------------
# Главный принцип

HashCenter не должен становиться сложнее.

Он должен становиться умнее.
