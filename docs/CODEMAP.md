# HashCenter Code Map

Version: R0.1

-------------------------------------------------------------------------------
# Назначение

Данный документ описывает движение данных внутри HashCenter.

Перед добавлением новой функциональности разработчик (или ИИ) обязан определить:

- в какой поток данных встраивается изменение;
- какие компоненты уже участвуют в обработке;
- где должна находиться новая логика.

Если новый функционал не вписывается ни в один существующий поток, необходимо пересмотреть архитектуру до написания кода.

# Правила внедрения новой функции

Перед написанием кода определить:

Какой сценарий изменяется?

Какие сервисы уже существуют?

Какой Repository уже существует?

Какой Handler уже существует?

Какая структура данных уже существует?

Если существующая реализация позволяет выполнить задачу, новая не создаётся.

-------------------------------------------------------------------------------
# Запрещённые действия

Handler вызывает SQL напрямую.

Handler запускает Hashcat.

Repository вызывает HTTP.

Repository вызывает WebSocket.

Hashcat вызывает HTTP.

Scanner изменяет базу данных.

UI содержит бизнес-логику.

-------------------------------------------------------------------------------
# Правило минимального пути

Любая новая возможность должна быть встроена в существующий поток данных.

Создание нового потока допускается только при невозможности использования существующего.

-------------------------------------------------------------------------------
# Перед написанием кода ИИ обязан

1. Найти соответствующий сценарий.
2. Определить точку расширения.
3. Использовать существующие сервисы.
4. Не создавать параллельные механизмы.
5. Минимизировать количество изменяемых файлов.
6. Проверить, что новый код не нарушает поток данных.

Если хотя бы один пункт нарушается, необходимо остановиться и объяснить причину.
